# 漏洞报告 A：www.sunoasis.com.cn PbootCMS API 签名/时间戳校验失效导致匿名读取与未授权写入

> 提交形态说明：本报告聚焦单一根因（PbootCMS API 鉴权缺陷）及其直接衍生影响。
> 文档中心（info.sunoasis.com.cn）问题属不同根因，见独立报告 B。

## 一、基本信息

| 项目 | 内容 |

| 漏洞名称 | www.sunoasis.com.cn（PbootCMS）API 网关签名/时间戳校验失效，致历史表单个人信息匿名可读、人才推荐数据可被任意伪造写入 |
| 受影响资产 | `www.sunoasis.com.cn`（特变电工新疆新能源股份有限公司官网，PbootCMS ≥3.2.5，宝塔环境） |
| 漏洞类型 | CWE-287（认证不当）+ CWE-359（个人隐私信息泄露）+ CWE-284（访问控制缺失，未授权写入） |
| 危害等级 | **中危至高危候选**（单项缺陷为中危：鉴权绕过；因涉及真实个人信息泄露 + 业务数据写入闭环，叠加后建议平台按 PII 范围与资产重要性裁量） |

## 二、漏洞描述

官网部署 PbootCMS 内容管理系统，对外 API 网关为：

```
https://www.sunoasis.com.cn/api.php        （PATHINFO 路由：/api.php/{模块}/{动作}/{参数}/）
```

官方 PbootCMS 的 API 认证要求请求同时携带 `appid`、`timestamp`、`signature` 三个参数，以 `signature = md5(md5(api_appid + api_secret + timestamp))` 双层 MD5 校验并强制 15 秒时间窗防重放。

实测确认：**该站点服务端实际未校验签名与时间戳**——任意非空 `appid` 即可通过全部接口认证，防重放机制整体失效。页面注入的 `appid='admin'` 为官方默认值且未修改。经与 PbootCMS 官方仓库（V3.2.5→V3.2.23 git 历史）行为对照，官方实现在同等配置下强制三参数校验；目标站点的实际行为偏离官方实现，具体修改方式以资产方服务器核查为准。

在此认证缺陷之上，实测确认两类影响（均为匿名可复现）：

1. **个人信息泄露**：人才推荐表单的历史提交数据（真实姓名、手机号等）可被任意第三方读取；
2. **未授权写入**：同一表单面的提交接口完全开放，任何人可伪造人才推荐数据入库（已以单条带标记测试记录完成写读闭环验证）。

## 三、影响一：个人信息匿名可读

```http
POST /api.php/cms/form/ HTTP/1.1
Content-Type: application/x-www-form-urlencoded

appid=x&fcode=1&page=1
```

返回 2 条真实「内部推荐」人才推荐记录（2022-2023 年），字段包括：

- 推荐人姓名 / 被推荐人姓名（真实姓名两组）
- 手机号两组（完整值已脱敏留存于本地取证，本报告不展示）
- 岗位与所在地
- 提交者 IP、操作系统、浏览器
- 内部审计字段：create_user / update_user 账号名

**公开性判定**：该表单无任何前台展示页面，数据仅应存在于后台管理界面——确定属于非公开个人信息。《个人信息保护法》合规风险直接成立。

## 四、影响二：未授权写入（数据污染）

```http
POST /api.php/cms/addmsg/
appid=x&user_push=SECURITY-TEST-DO-NOT-PROCESS&push_name=安全测试数据请忽略
&push_position=penetration-test&push_number=T0000&push_where=SECURITY-TEST
&user_tel=10000000000&push_tel=10000000001

→ {"code":1,"data":"留言提交成功！"}
```

提交后通过 cms/form 回读确认：**fcode=1 记录数由 2 条变为 3 条，测试记录 id=4 已入库且可被后续读取**——完整写读闭环。攻击者可批量伪造人才推荐数据污染招聘流程。

**测试记录处置声明**：
- 该记录所有字段均带 `SECURITY-TEST / 安全测试数据` 明显标记，便于识别；
- 记录仍留存在生产库中（id=4），**请求资产方或平台协助清理**，测试方不再对该记录做任何删除或修改操作；
- 除本次单条验证外未进行任何后续写入。

## 五、认证缺陷证据（根因）

页面每次渲染注入服务端签名三元组（index.html 内联脚本）：

```javascript
let siteKeys = { appid: 'admin', timestamp: '1787679036', signature: '8d0b50...' };
```

绕过矩阵实测（全部 POST /api.php/cms/search/）：

| 参数组合 | 结果 |
|---|---|
| 仅 `appid=x`（任意值） | ✅ 完全放行 |
| `appid=x&timestamp=0`（1970 过期时间戳） | ✅ 放行 |
| `appid=admin&signature=deadbeef`（错误签名） | ✅ 放行 |
| 不带任何参数 | ❌ 拒绝（唯一拦截条件是"appid 缺失"） |

**官方实现对照**：PbootCMS 官方仓库 V3.2.5→V3.2.23 中，`apps/common/ApiController.php::checkAccess()` 在 `api_auth` 开启时强制 appid+timestamp+signature 三参数校验（双层 MD5 + 15 秒窗口）；模板标签 `{pboot:appid}/{pboot:signature}` 注入机制与目标一致。目标站点页面正常注入签名三元组但服务端不执行校验——行为偏离官方实现，属服务端配置/代码级缺陷，具体修改点需资产方在服务器上核查。

**假阳性排除声明**：对同接口面曾专项排查 SQL 注入候选（ext_*/rorder 等参数），经真/假条件对拍与特殊值判别实验确认为引号精确字符串比较，不构成注入。本报告不包含未经验证的攻击面推测。

## 六、危害影响汇总

1. **个人信息保护合规风险（最高优先）**：求职者/被推荐人真实姓名+手机号+IP 公网匿名可读，违反《个人信息保护法》最小授权原则；
2. **业务数据完整性**：人才推荐流程可被任意第三方伪造数据污染，已有写入闭环证明；
3. **横向情报价值**：API 全部 19 个有效路由结构、站点配置、内部编辑账号名等系统信息暴露，为后续定向攻击提供基础（辅助性影响）。

## 七、修复建议

1. **立即恢复完整签名校验**：补齐 timestamp（±15 秒）+ signature 双层 MD5 校验，或升级至官方最新版后重新配置；修改默认 `api_appid='admin'` 并轮换 api_secret；
2. **关闭公网表单接口**：cms/form、cms/msg、cms/addmsg、cms/addform 若无移动端需求应在网关层禁用；
3. **PII 应急处置**：清除或脱敏存量表单中的手机号等个人信息；按《个人信息保护法》评估通知义务；
4. **清理测试写入记录**：删除 id=4 的 SECURITY-TEST 标记记录（定位信息见第四节）；
5. **纵深防御**：/api.php 迁出公网或加访问白名单；避免接口异常回显泄露绝对路径与账号名。
