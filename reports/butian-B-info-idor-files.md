# 漏洞报告 B：info.sunoasis.com.cn 隐藏文档详情接口越权访问与受保护本地文件匿名下载

> 提交形态说明：本报告与 PbootCMS API 鉴权缺陷（报告 A）根因不同、系统不同，独立提交。
> 依据证据边界原则，本报告**不包含**任何内部文档文件本体、完整下载路径或全量文档清单；
> 敏感性证明仅以文件指纹（MD5）、页数与脱敏后的局部标识呈现。

## 二、漏洞描述

资料中心 `info.sunoasis.com.cn` 的公开列表接口每页仅展示少量文档；实测发现其**详情接口不校验资源归属**——列表中不可见的文档，只要按 ID 枚举详情接口即可完整读取标题、编号、外发链接等元数据。

进一步发现：部分文档的详情返回值携带站内存储直链 `/backend/storage/files/<32位十六进制>.<扩展名>`，该存储路径**无任何鉴权校验**，文件本体可直接匿名下载。

两个缺陷组合后，攻击者可从"不可见的文档列表"出发系统性获取隐藏文档的元数据乃至文件本体。

## 三、影响一：隐藏文档详情越权读取

```http
POST /backend/v1/detail HTTP/1.1
Content-Type: application/json

{"filesId": <N>}
```

- 公开列表可见文档约 40 篇；
- 按 ID 枚举详情接口实测可达 **119 条列表不可见文档**（ID 唯一，范围为 19–175），均返回完整元数据（标题/编号/外发链接/统计字段）。

其中 53 条携带指向企业文档云的外发链接。此类链接的匿名预览页可渲染文件名、大小、版本、分享人姓名等元数据；全文预览需登录会话，本次测试未验证亦未尝试突破。

**验证边界**：119 条为逐条枚举并确认"列表不可见但详情可读"的集合计数；53 条为该集合中携带外发链接的可核验子集（ID 唯一可交叉核对）。

## 四、影响二：受保护本地文件匿名下载

```http
POST /backend/v1/detail {"filesId":115}
→ data.file: /backend/storage/files/0598****.pdf

GET /backend/storage/files/<hash>.pdf
→ 200 OK, application/pdf, 3,424,952B
```

119 篇隐藏文档中 **13 篇**携带本地文件直链。

### 验证方法与证据边界（如实分层）

- **路径来源**：13 条路径均来自 detail 接口的实际响应返回值（非猜测构造）；
- **匿名访问验证**：对其中 **2 条代表样本**（内部手册、公开重复件各 1）执行了不带会话的实际 GET，均获 200 OK 并核验 Content-Type/长度/%PDF 头；内部手册完成"返回路径→匿名成功访问→MD5→首页标识"完整链条；
- **其余 11 条**：仅保存脱敏路径标识（hash 化文件名），未下载本体——为避免扩大内部资料留存范围的数据最小化选择，不作为逐条下载结论；
- 本报告核心危害主张建立在**至少一份明确标识内部资料的文件可被匿名获取**这一已完整验证事实上，而非"13 个文件全部泄露"。

### 提交前当前状态复核（2026-08-26，受限最小验证）

对已知的 filesId=115（内部手册）路径执行**一次受限 Range GET**（仅请求前 512KiB，只读响应头与前 8 字节，未保存任何内容）：

| 观察项 | 结果 |
|---|---|
| HTTP 状态 | **206 Partial Content** |
| Content-Type | `application/pdf` |
| Content-Range | `bytes 0-524287/3424952`（服务端暴露完整对象长度 3,424,952B，与归档一致） |
| 文件头（前 8 字节） | `%PDF-1.7` |
| 认证 | 请求无 Cookie、无 Authorization、无 Token |
| 内容保存 | 未保存（仅验证响应特征） |

结论：**提交时该文件仍可被匿名部分获取**，且响应特征与测试期归档一致（同一 3,424,952B 对象）。未对 13 条路径做全覆盖复验，亦未下载完整文档；"当前仅验证单一路径、未覆盖全部"如实声明。

### 集合关系图（119 → 13 → 1）

```
119 条列表不可见文档详情记录（逐条枚举，ID 唯一）
├─ 106 条：无可匿名读取的站内本地文件路径
│   └─ 其中 53 条：带企业文档云外发链接；匿名仅见元数据，全文访问未验证
└─ 13 条：详情返回站内本地文件路径
    ├─ 1 条：内部资料手册 —— 完整验证链（核心危害依据）
    ├─ 10 条：非公开/下线产品图（PNG）—— 影响面陈述，不作定级核心
    └─ 2 条：与公开列表字节级相同的画册/单页 —— 不计入危害
```

### 敏感性判定（三重验证，按强弱分层）

对 13 个文件的哈希对照、检索可得性与文件自身标识分别评估：

| 判断维度 | 强度 | 提交表述 |
|---|---|---|
| 文件自身标识 | 强 | 手册首页明确标注「内部资料 请勿外传」 |
| 匿名可访问性 | 强 | 匿名成功响应 + 文件大小 + MD5 + 局部脱敏截图 |
| 不在公开集合 | 中 | 与当时公开列表集合的字节级哈希对照未见相同文件 |
| 搜索不可得 | 辅助 | 本次检索未发现该手册的公开来源 |
| 涉及人员姓名 | 中 | PDF 内含编制/校准人员信息（姓名不在报告中展示） |

核心定级依据为前三项的组合；搜索不可得仅为辅助佐证。10 张产品图作为影响面陈述，不计入定级核心；2 个公开重复件不计入任何危害。

**取证指纹**（供平台复核，文件本体不上传）：

## 五、危害影响汇总

1. **内部资料外泄（最高优先）**：明确标注「内部资料 请勿外传」的技术手册可被任意匿名者下载，且泄露编制/校准人员真实姓名；未发布产品外观图一并暴露；
2. **信息资产管理失效**：大量列表不可见文档可被系统性枚举，暴露文档平台访问控制缺失；
3. **辅助情报价值**：文档编号体系、组织架构线索（人员名）为定向攻击提供基础。

说明：另有约 170 余篇历史港股公告类内容同样可被枚举，因其本属历史合规披露物、保密性弱，**不作为本报告危害论据**，仅在修复时建议一并治理。

## 六、修复建议

1. **立即下架敏感文件**：对 13 篇本地文件逐一评估去留；「内部资料」级文档严禁挂载于公网可达存储；
2. **storage 目录加鉴权**：`/backend/storage/files/` 增加会话/签名校验，或移出 Web 根由后端受控下发；
3. **详情接口补齐授权**：`/backend/v1/detail` 校验资源对匿名用户的可见性，或要求会话令牌；
4. **清理冗余入口**：与公开列表重复的隐藏条目合并去重，消除双入口不一致；
5. **审计外发链接**：53 篇携带企业文档云外发链接的文档复核分享范围是否过宽。
